Overview

Beta — actively under development

This assistant is new and still being tested. It can make mistakes: hallucinated file paths, incomplete multi-step actions, or (rarely) chemically incorrect results that still report as successfully completed. Always verify important results yourself (see Limitations & Good Practices below) before relying on them. Feedback and bug reports are welcome — contact Abdallah Ammar.

The cluster provides a chat-based assistant, powered by a locally-hosted LLM, that can check cluster status and prepare and submit calculations on your behalf. It runs entirely on cluster hardware — no data leaves the cluster.

What it can do today

  • Check the job queue, node/partition availability, and job status
  • Search available software modules
  • Prepare and submit Gaussian quantum chemistry jobs: single-point, optimization, frequency, transition-state, IRC, and TDDFT (excited-state) calculations, with optional implicit solvation

Support for other software packages (CP2K, ORCA, etc.) is planned but not yet available.

Getting Started

Access the assistant at: http://lpct-llm.lpct.site.univ-lorraine.fr:3000

Choosing a model

Two models are currently available, with different strengths:

Model Best for Notes
Qwen3-Coder-30B-A3B Multi-step requests (e.g. "prepare, submit, and check the status of this job" in one message) Slower, but reliably completes chains of several actions
Qwen3-8B Single, simple requests (checking status, one calculation step at a time) Faster; for anything with more than one step, guide it turn-by-turn rather than asking for everything at once

Tip: if a multi-step request stalls partway through (e.g. it prepares the job but doesn't submit it), just ask it to continue with the next step explicitly.

Example Prompts

Checking cluster status

> What partitions have idle nodes right now?
> Check the status of my jobs

Searching for software

> Is there a gaussian module available? Show me the versions.

A simple Gaussian calculation

> Create a Gaussian workspace called "water-test". Then prepare a single-point
calculation using method B3LYP, basis set 6-31G(d), job type sp, on the
taras2-6230r partition, with geometry provided inline as:
O 0.000000 0.000000 0.119262
H 0.000000 0.763239 -0.477047
H 0.000000 -0.763239 -0.477047
Then submit it and check its status.

Optimization with implicit solvation

> Create a Gaussian workspace called "ethanol-opt". Then prepare a calculation
using method PBE, basis set 6-31G(d), job type opt, solvation model SMD,
solvent Ethanol, on the taras2-6230r partition, with geometry provided
inline as: [your coordinates]. Then submit it and check its status.

TDDFT excited states

> Create a Gaussian workspace called "water-td". Then prepare a calculation
using method B3LYP, basis set 6-31G(d), job type td, nstates 3, solvation
model CPCM, solvent Water, on the taras2-6230r partition, with geometry
provided inline as: [your coordinates]. Then submit it and check its status.

Geometry from a file or PubChem

Limitations & Good Practices

Always provide a real 3D starting geometry for optimizations

A geometry where atoms are exactly collinear or otherwise artificially symmetric can cause the optimizer to converge on the wrong structure (a saddle point instead of a true minimum) with no error message. Use a genuine 3D geometry — from a reference source, a previous calculation, or PubChem — rather than a simplified/idealized one.

A "COMPLETED" job is not proof the calculation succeeded

Slurm reports a job as completed as soon as Gaussian exits without a system-level error — this does not guarantee the calculation converged correctly. Always check the .log file for Normal termination, and for optimizations or frequency calculations, confirm there are no imaginary frequencies (a nonzero count means you found a saddle point, not a minimum).

For large or complex molecules, prefer supplying geometry from a file already on the cluster or fetched from PubChem, rather than typing coordinates directly in the chat.

Excited-state (TDDFT) optimizations preserve the symmetry of your starting geometry by default. If you expect a symmetry-broken excited-state structure, you may need to start from a slightly distorted geometry.
